一、调研知识图谱商业项目——阿里巴巴数字商业知识图谱

 

1. 项目介绍​

知识图谱是用图的方式描述实体以及实体之间的关联关系，在当今的数字时代的高质量智能化发展方面，起到了越来越重要的作用，涉及越来越多的领域。阿里巴巴作为互联网公司，充分利用知识图谱的优势，将知识图谱在语义搜索、智能问答、推荐计算、语言理解、大数据分析等技术领域得到应用，在多个方面发挥着基础性作用。

具体而言，针对阿里集团旗下天猫、淘宝、饿了么等多个零售业务单元，阿里巴巴数字商业知识图谱利用知识图谱已经开发了智能商品发布、商品管理、品类规划、平台治理等多个落地的智能化应用场景，让知识图谱技术在商业项目中起到作用，阿里巴巴数字商业知识图谱是个值得调研的话题。

 

下面，对该项目的用户需求和功能需求进行列举。

2. 用户需求​

用户需求通常是从用户的角度描述的需求。这些需求关注的是用户想要达到的目标和解决的问题。对于阿里巴巴数字商业知识图谱来说，这里的需求可以分为 商家需求、消费者需求、平台需求。

1. 商家需求​

对于商家需求来说：商家需要使用智能商品发布的功能、商品信息补全功能、销售策略支持功能等。

  • 智能商品发布：商家希望快速且准确地发布商品，减少人工输入时间，提高信息准确性。

  • 商品信息补全：在发布商品时，希望系统能自动补全商品的关键信息，提升发布效率。

  • 销售策略支持：需要系统提供市场趋势和消费者偏好信息，以优化销售策略。

2. 消费者需求​

对于消费者需求来说，用户在搜索商品时希望获取准确且个性化的推荐，有更好的使用体验、商品信息的准确性、有完备的售后服务保障。

  • 高效搜索和推荐：消费者希望在搜索商品时获得准确且个性化的推荐，提高购物体验。

  • 商品信息准确性：消费者希望商品信息准确无误，避免购买到信息不符的商品。

  • 售后服务保障：希望在售后服务方面得到系统的有效支持，包括快速处理退换货、投诉等。

3. 平台需求​

平台对商品和用户信息要起到实时监控的目的，这要求要有商品实时管控的功能。同时，可以利用知识图谱，进行市场趋势分析和局的支持，用以优化平台运营。也就是说：

  • 商品实时管控：平台需要实时监控和管理商品信息，确保商品信息的准确性和合法性。
  • 市场分析和决策支持：平台希望通过知识图谱进行市场趋势分析和决策支持，优化平台运营。

 

3. 功能需求​

功能需求是对系统应具备的功能和行为的具体描述，这里的内容需要说明系统需要实现的功能和业务规则。对于阿里巴巴数字商业知识图谱来说，这里的功能需求有知识图谱构建与维护、提供知识服务接口、提升消费者体验、智能商品发布。

1. 知识图谱构建与维护​

要求系统能在低资源的条件下也能构建知识图谱，支持一些基本的关系抽取功能。除此之外，还要有能够自动补全知识图谱缺失信息和进行一定推理的的能力，提升图谱的完整性，服务能力足够智能。

2. 提供知识服务接口​

要求系统设置的一系列知识服务接口是标准化的，能够支持第三方应用系统依据标准化接口接入知识图谱服务。

同时要具备知识图谱的实时更新和维护功能，能够确保知识的时效性和准确性。

3. 市场分析和决策支持​

知识图谱不能仅有面向个人用户的简单推荐推理能力，还要要求有多模态预训练模型的能力，从多个模态的数据来支持知识图谱的构建，从而提升分析的准确性。

系统要有能够通过知识图谱对市场趋势分析和预测的能力，支持业务决策。

4. 提升消费者体验​

对于消费者个人用户，应该使用系统通过应用知识图谱技术来实现个性化推荐，提升搜索精准度和用户满意度；对于平台人员，系统能够提供市场趋势和消费者行为的决策树，辅助前台运营。

5. 其它......​

对于更详细的功能描述，还有以下这些。

  1. 商品信息自动补全：
    • 输入商品基本信息，系统自动从知识图谱中提取相关信息并补全，如品牌、规格、产地等。
    • 提供多语言支持，确保不同市场的商品信息准确补全。
  2. 渠道识别和对齐：
    • 系统自动识别不同渠道中的相同商品，并对其信息进行统一管理和对齐。
    • 提供跨渠道库存状态实时更新功能，确保商品流通顺畅。
  3. 智能搜索和推荐：
    • 系统根据用户搜索历史和偏好，实时推荐相关商品。
    • 支持语音、图像等多种输入方式，提高搜索的便捷性和准确性。
  4. 多源信息融合和校验：
    • 系统整合来自不同来源的信息，进行语义融合和校验，确保商品信息的准确性和完整性。
    • 提供实时报警功能，当检测到异常或违规商品信息时，系统自动通知相关管理人员。
  5. 市场趋势分析和预测：
    • 系统通过知识图谱对市场数据进行分析，提供实时的市场趋势报告和预测。
    • 支持多维度数据分析，如销售数据、用户行为数据、社交媒体数据等，提供综合的市场洞察。

二、相关技术学习——Nginx

 

Nginx 介绍​

Nginx是什么呢？它是一个高性能的web服务器和反向代理服务器，相似的软件还有使用Go语言编写的 caddy。

我们使用Nginx来处理静态文件特别方便，在我们项目中，前端项目通过 npm run build生成的静态文件就可以放到Nginx的查找目录处，从而使用域名访问时，通过设定的域名规则，展示想要展示的内容。

反向代理：如果你本地有个服务在某个端口上运行，你不想直接把这个端口暴露给用户，这时候你可以让nginx作为中间人，将用户的请求转发到后台应用上，就像你去酒吧的柜台拿酒，你会问柜员要你要的酒，而柜员就会根据你要的东西去后面的酒柜拿酒来，柜员在这里就充当一个代理的角色。在项目中，我们就用Nginx的反向代理，将互联网来的80端口请求转发到前后端服务，从而有条不紊的运行。

负载均衡：如果你的网站流量很大，一台服务器顶不住，Nginx可以将流量分摊到多台服务器上，这样每台服务器都承载差不多的压力，有效解决了访问量过大网站卡顿卡死的情况。

环境介绍​

nginx使用最新版本，运行平台在云服务器Ubuntu22.04系统，语言为 bash/shell。

三、两个自动化测试软件——Github action 和 Selenium

 

Github action​

介绍​

GitHub Actions 是一个自动化测试工具，它是 GitHub 提供的 CI/CD 工具，可以用来自动化软件开发工作流，包括：

  • 自动化构建：每次代码推送或者 pull request 时触发构建任务。
  • 自动化测试：配置测试套件，自动执行单元测试、集成测试等。
  • 自动化部署：在测试通过后自动部署应用。

优点：它非常突出的优点就是集成在Github仓库中，通过编写一个yaml文件，在push或者拉取代码时就会执行一系列流程，很方便。

应用​

在我们的项目中，使用了 Github action 自动化打包应用和部署项目文档，但是这属于自动化部署的应用，现举例自动化测试的例子。

name: CI

on:
  push:
    branches:
      - main
  pull_request:
    branches:
      - main

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
    - name: Checkout repository
      uses: actions/checkout@v2

    - name: Set up Node.js
      uses: actions/setup-node@v2
      with:
        node-version: '14'

    - name: Install dependencies
      run: npm install

    - name: Run unit tests
      run: npm test

    - name: Set up Python
      uses: actions/setup-python@v2
      with:
        python-version: '3.8' 

    - name: Install Python dependencies
      run: |
        python -m pip install --upgrade pip
        pip install -r requirements.txt 

    - name: Run Python file
      run: python test_demo.py

四、软件开发模型——演化模型

先考虑传统软件生命周期模型，瀑布模型。瀑布模型是基于需求分析—软件需求—分析—程序设计—编码—测试—运行的工作流程来的，它每个阶段通过审核和文档输出来驱动。它的每个开发活动依赖上一项活动的输出。优点是每个阶段能够正常的衔接，能够及时发现问题。但考虑我们的项目开发周期短，开发时间紧张，并且考虑到我们的需求可能在过程会适量调整，所以成功周期长、只依赖文档来评估进度决定了不是最适合我们的项目。于是，考虑了演化模型。演化模型是在瀑布模型的基础上，一次性开发难以成功，因此，演化模型提倡进行“两次开发”，分别是试验开发和产品开发。每个开发阶段按照瀑布模型进行具体开发活动。首先它适用于需求不清，开发周期短的中小型系统，与我们的项目情况较为符合，其次，在开发过程中对需求的重新提出也能很好地及时在第二次产品开发时予以修正。根据演化模型，给出了下面项目进度计划（甘特图）。
